# AAA Voice AI Manager

Цифровой голосовой сотрудник для бизнеса: принимает звонки, консультирует по базе знаний,
фиксирует заявки, записывает на приём и собирает аналитику по разговорам.

## Возможности

- Приём и ведение диалога с распознаванием намерения клиента
- Ответы по базе знаний компании с версионированием документов
- Создание заявок и запись на приём с удержанием слота
- Передача разговора живому оператору по критическим словам
- Аналитика: конверсия в заявки, неотвеченные вопросы, стоимость и длительность звонков
- Доставка событий во внешние системы через очередь с повторными попытками

## Технологии

- Next.js 16 (App Router), React 19, TypeScript
- PostgreSQL (Neon) + Drizzle ORM
- Better Auth — вход по email и паролю
- Tailwind CSS v4, shadcn/ui
- Vitest — юнит- и интеграционные тесты

## Запуск

```bash
pnpm install
pnpm dev
```

Приложение откроется на [http://localhost:3000](http://localhost:3000).

### Переменные окружения

| Переменная                        | Назначение                                        |
| --------------------------------- | ------------------------------------------------- |
| `DATABASE_URL`                    | Подключение к PostgreSQL                          |
| `BETTER_AUTH_SECRET`              | Секрет подписи сессий, минимум 32 символа         |
| `VOICE_PROVIDER_WEBHOOK_SECRET`   | Проверка подписи входящих вебхуков от телефонии   |
| `VOICE_TELEPHONY_ROUTING`         | Маршрутизация номеров по компаниям, JSON-массив   |
| `VOICE_MODE`                      | Запрашиваемый режим работы, по умолчанию `demo`   |

Секрет для сессий генерируется так:

```bash
openssl rand -base64 32
```

## Доступ и разделение компаний

Все данные закрыты входом, а каждая компания видит только свои звонки, заявки и базу знаний.

Аккаунт привязывается к компании кодом приглашения при регистрации. Код проверяется на сервере,
и компания берётся из записи приглашения, а не из данных формы — иначе подмена поля в запросе
открыла бы доступ к чужим звонкам. Коды хранятся в таблице `voice_invites` и имеют лимит
использований и срок действия.

Идентификатор компании во всех выборках берётся из сессии. В маршрутах, где он есть в адресе,
значение дополнительно сверяется с сессией и при несовпадении возвращается 404 — существование
чужой компании не подтверждается.

## Подключение телефонии

Схему выбирает каждая компания отдельно:

- `forwarded` — звонок приходит на существующий номер компании, а оператор переадресует его на
  SIP-адрес ассистента. Номер остаётся у компании, менять оператора не нужно.
- `rented` — номер арендуется у провайдера (Twilio или Telnyx) и сразу указывает на ассистента.

Живая конфигурация задаётся переменной `VOICE_TELEPHONY_ROUTING` — JSON-массивом:

```json
[
  {
    "companyId": "clinic-almaty",
    "kind": "forwarded",
    "publicNumber": "+77273002233",
    "sipUri": "sip:assistant@voice.example"
  },
  {
    "companyId": "beauty-astana",
    "kind": "rented",
    "publicNumber": "+77172447788",
    "provider": "twilio"
  }
]
```

Без этой переменной берутся demo-номера без SIP-адресов, то есть звонки остаются имитацией.
Незаполненное обязательное поле рабочей настройкой не считается: страница «Интеграции» показывает,
чего именно не хватает, вместо того чтобы объявить готовность.

Номера приводятся к виду E.164, поэтому `+7 (727) 300-22-33` и `87273002233` — один и тот же номер.
Если один номер заявлен двумя компаниями, звонки на него не принимаются вовсе: при любом другом
поведении разговор с равной вероятностью попал бы в чужой кабинет.

Компания входящего события определяется по набранному номеру из подписанного тела вебхука.
Заголовок `x-voice-company` подписью не покрыт, поэтому расхождение с номером отклоняется.

## Режимы работы

- **demo** — диалоги проигрываются по сценариям, телефония и платные API не используются
- **live** — реальные звонки через провайдера телефонии

Режим задаётся для каждой компании отдельно в её настройках.
